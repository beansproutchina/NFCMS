# 第 3 步 · 设计文档(待审) — 子 agent 执行说明

## 目标
产出一份**完整到任何人可照着从零实现**的设计文档,并用 `ExitPlanMode` 交用户批准。

## 输入(编排器传入)
6 轴定案 + 第 2 步的现状问题清单/数据可行性结论/借鉴点。

## 必读参考
`reference/theme-api.md`(分类约定、模板选择、`theme.config.ts` 契约、`context`、`theme_<name>_*` 机制)。

## 文档必含小节
1. **信息架构表**:`页面 → 模板文件 → 路由/机制 → 数据来源 → 是否可配`(覆盖 6 轴选定的每个页面)。
2. **分类约定表**:每个约定分类的 `slug / list_template / content_template / article_data_fields`(以及 weight 决定的首页顺序)。
3. **`article.data` 字段约定**:每类文章的自定义字段(键名 + 含义 + 示例),对应第 2 步"需入 data"的结论。
4. **`theme_<name>_*` 配置清单** → 将写入 `configSchema`:每项 `key / label / type / group` + **降级策略**(空则隐藏,绝不假数据)。
5. **菜单 location 约定**:header/top/quicklinks/footer 各放什么;默认菜单项;是否自定义路由页(/about /contact /search)。
6. **视觉系统**:配色(CSS 变量清单)、字体(在 `init()` 加载哪些)、间距/组件基调,呼应第 1 步的风格轴。
7. **模板文件清单**:要新增/重做哪些 `.vue`(含共享 `components/`、`lib.ts`)。
8. **演示数据计划**:第 6 步要造哪些分类/文章/配置的概述。
9. **明确不做**:划边界(如不改后端、不做暗色、表单用 mailto、不做无数据支撑的展示)。

## 设计准则(写进文档时遵守)
- **约定优于兜底**:需要特定数据才亮的区(如首页焦点图需置顶),写明"交付时告知客户必须配置,否则留空",**不设"抓别的顶上"的兜底**(见 patterns.md 反面教材)。
- 每个展示位标注"无数据时的表现"(隐藏 / 空态)。
- 非文章页的数据来源与第 1 步第 4 轴一致(推荐分类+文章驱动)。

## 产出与门禁
把文档通过 `ExitPlanMode` 呈现,**等用户批注/批准**。用户要改 → 交回编排器决定回第 2 步或重跑本步;**未获批准不得进入开发**。
