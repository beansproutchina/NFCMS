# 第 1 步 · 提问(Ask) — 子 agent 执行说明

## 目标
用**分两批的自适应提问**,定案 6 条正交轴,给整个主题定骨架。

## 输入(编排器传入)
- 用户初始 query(可能已明确若干轴)。
- 目标主题名 `name`(如无,先问/让用户定)。

## 原则
- 6 条轴**互不重叠**,但**不要一次全抛**。先问 2 个地基轴,据答案**从该类站点运营者视角**重想需求,把其余 4 轴的选项**换成贴合该场景的具体项**再问。
- **跳过条件**:query 已明确某轴就不问该轴;全明确则直接产出定案(标注"据 query 推断"),不必发问。
- 用 `AskUserQuestion`。每题给 2–4 个选项 + 简短 description;推荐项放第一并标"(推荐)";multiSelect 用于可多选题。

## 批次 A(先问,2 题 —— 决定一切的地基)
1. **站点类型 / 受众**:博客·内容站 / 工作室·作品集 / 学校·机构官网 / 个人主页 / 文档站 / 电商·落地页。
2. **视觉风格**:极简现代 / 编辑排版 / 粗野主义 / 商务稳重 / 活泼;并问**是否要暗色模式**。

## 批次 B(据 A 的答案定制选项后,4 题)
拿到"类型 + 风格"后,先在心里为该类站点列出"运营者真正需要什么",据此定制以下四轴的**具体选项**(不要泛泛的通用清单):

3. **页面清单**(multiSelect):给该类型的**合身默认组合**。例:
   - 工作室 → 作品集+项目详情 / 服务 / 团队 / 关于 / 联系
   - 学院官网 → 新闻 / 通知公告(公文版式?) / 师资 / 院系概况 / 搜索
   - 文档站 → 指南 / API 参考 / 更新日志 / 搜索
   - 个人主页 → 作品 / 博客 / 关于 / 联系
4. **非文章页的数据来源**(关于/服务/团队等):分类+文章驱动(CMS 原生、可后台编辑,**推荐**) / 主题配置驱动 / 混合。
5. **可配置项**(multiSelect → `theme_<name>_*`):按类型给**最该配的项**。例:工作室 → Logo/社交/联系邮箱/Hero 文案·CTA;学院 → Logo/页脚地址电话/公安备案/二维码;个人 → 头像/社交/关于文章 slug/主色。
6. **导航与结构**:据已选页面**推荐** header/footer 菜单项与 location(是否需要 top 顶栏 / quicklinks 快速通道)、是否要自定义路由页(/about /contact /search)、是否二级下拉。

> 若该类站点有场景特有取舍(学院公文版式、电商价格来源、文档版本切换…),在批次 B 一并作为选项问清。

## 产出(交回编排器)
一份 **6 轴定案**(逐轴写清结论 + 依据是"用户答复"还是"query 推断"),作为第 2/3 步的输入。

## 门禁 / 交接
两批问完、拿到用户答复即完成。把定案交回编排器;不要顺手开始调研或写代码。
