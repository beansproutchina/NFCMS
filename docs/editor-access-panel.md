# 文章编辑器:头部动作区 + 「权限」面板 —— 前端重设计

> 状态:**已实现**。范围:只改前端表现 —— **后端一行没动**(字段、接口、判定规则全部沿用 [public-access.md](public-access.md))。实现中的三处偏差见 §11。

---

## 1. 现状:四处散落 + 三种生效时机 + 裸字母

| 位置 | 控件 | 何时生效 |
|---|---|---|
| 头部 | 状态 chip + 发布/撤下按钮 | 立即(`lifecycleAPI`) |
| 属性面板 | 访问受众 / 公开摘要 两个下拉 | **保存后**(文章字段) |
| 属性面板 | 定时发布 DatePicker + 按钮 | 立即(`lifecycleAPI`) |
| 属性面板底部 | `R U D publish V` 五个字母 toggle | 立即(`/acl`),且新建文章时整块不显示 |

暴露底层实现的具体点:

1. **`R U D publish V` 裸字母** —— 后端 access 字符串直接当 UI。
2. **`V`(能看)和 `R/U/D/publish`(能改)挤在同一行 toggle** —— 两个正交的轴压成一个控件。
3. **「访问受众」「公开摘要(摘要墙)」是内部术语** —— 作者读不出"这到底会发生什么"。
4. **三种生效时机混在一屏**,没有任何标注。
5. 新建文章时授权区块直接消失,不给解释。

## 3. 「立即生效」带来的两处修订(需你确认)

改成独立面板 + 立即生效后,有两点与原答案冲突,我按"立即生效"的语义调整,请确认:

### 3.1 新建文章时按钮不可用

立即生效需要文章 id:`audience`/`teaser` 要 PATCH 这一行,授权要打 `/acl/articles/:id`。新建态两者都没有落脚点。

→ **新建文章时按钮禁用**,提示「保存后可设置权限」。
(原先选"随保存提交"的一个主要收益就是新建态也能配,这个收益随改主意消失了。如果你要保住它,就得回到"随保存提交";两者不可兼得。)

### 3.2 存量授权的归一**只在用户动那一行时才写**

原答案是"归一到最接近的档位并提示已变更"。但在**立即生效**语义下,如果打开面板就把归一结果写回去,等于**用户什么都没点,他的细粒度授权就被静默改写了**。

→ 打开面板时只**显示**成最接近的档位 + 明确提示原值;**只有用户主动改动那一行**才发请求。没动过的行永远保持原样。

## 4. 头部动作区:三个按钮

**只保留三个**,状态由第三个按钮自己表达 —— 所以头部那个状态 chip 去掉(它是"多余的状态查看器")。

```
[←]  编辑文章                        [保存]  [权限]  [发布 ▼]
```

第三个按钮随状态换形:

| 文章状态 | 按钮 | 点击行为 |
|---|---|---|
| `hidden`(草稿) | **发布 ▼** | 主体=立即发布;`▼`=定时发布 |
| `scheduled`(定时) | **定时 08-01 09:00** | 弹框 → 取消定时(见 §4.2) |
| `visible`(已发布) | **隐藏** | 撤下,回到草稿 |

### 4.1 定时发布的入口

| 端 | 交互 |
|---|---|
| PC(≥1024px) | 主体按钮直接发布;点 `▼` 展开菜单,唯一项「定时发布…」→ 打开选时间的对话框 |
| 移动端(<1024px) | 无 `▼`。点「发布」先弹选择:**立即发布** / **定时发布…** |

→ **属性面板里那块「定时发布」DatePicker + 按钮移除**(同样是"多余"),时间选择改为对话框内完成。

### 4.2 定时状态下的按钮

按钮直接显示计划时间(如 `定时 08-01 09:00`),点击打开对话框。**给三个动作**,否则"改时间"和"直接发布"都要退化成两步(先取消、再重做):

```
┌─ 定时发布 ───────────────────────────────┐
│  计划于 2026-08-01 09:00 自动发布。        │
│                                          │
│  [ 2026-08-01 09:00  ▦ ]                 │  ← 改时间:改完点「更新」
│                                          │
│  [立即发布]   [更新时间]   [取消定时]      │
└──────────────────────────────────────────┘
```

三个动作都是同一个后端接口:`lifecycleAPI.transition('articles', id, {...})` —— 分别 `to:'visible'` / `to:'scheduled'` 带新时间 / `to:'hidden'`。

### 4.3 「预览」整体下架

预览**从前端移除**。理由(你的判断,记在这里免得以后有人"顺手加回来"):它打开的 `Preview.vue` **不套主题、不带样式**,渲染出来的东西和访客实际看到的差很远 —— 既没有验证价值,又要维护一条独立的令牌流程与路由。

移除范围(**后端端点保留不动**,将来重做时还要用):

| 删 | 位置 |
|---|---|
| 头部按钮 + `doPreview()` | `views/admin/Editor.vue` |
| `/preview` 路由 | `router/index.ts` |
| 预览视图 | `views/front/Preview.vue` |
| `contentAPI.previewToken` / `contentAPI.preview` 两个封装 | `api.ts`(`api.gen.ts` 是生成物,**不动**) |
| `action.preview` 与整个 `preview.*` 文案组 | `i18n.ts`(en + zh) |

将来重做时的正确做法(留给那时候):预览应当走**真实的主题渲染通路** —— 即前台路由带上令牌参数、由 `DynamicView` 正常套 layout 渲染,而不是另做一个裸页面。

### 4.4 面板结构

面板本体(用既有的 `AdminModal`,`max-w-lg`):

```
┌─ 权限 ───────────────────────────────────────────── × ─┐
│                                                        │
│  ┌ Message(warn) ────────────────────────────────┐    │
│  │ (i) 本文还是草稿,下面的设置暂不生效。发布后生效。│    │
│  └───────────────────────────────────────────────┘    │
│                                                        │
│  谁能看到这篇                                           │
│   (o) 跟随分类「动态」的设置                             │
│        └ 分类当前:所有人可见                            │
│   ( ) 所有人                                            │
│   ( ) 登录后可见                                        │
│   ( ) 仅我指定的人                                       │
│                                                        │
│   ── 选中「登录后可见」或「仅我指定的人」时展开 ──         │
│   ☑ 未登录的人可以看到标题和摘要                          │
│      不勾:未登录访客完全看不到这篇(列表里也不出现)。      │
│                                                        │
│  ────────────────────────────────────────────────────  │
│  访问与协作                                             │
│   张三(作者)      作者 · 始终可编辑            —        │
│   李四            [可查看      ▼]              ×        │
│   王五            [自定义 ⓘ    ▼]              ×        │
│      └ 原为:可读取、可修改、可删除(不含发布)             │
│   ─────────────────────────────────────────────        │
│   编辑部(角色)     可查看 · 来自分类「动态」   只读       │
│                                                        │
│   [+ 添加人员]                                          │
│   ┌ Message(secondary/简版) ─────────────────────┐     │
│   │ (i) 此处改动立即生效,无需保存。               │     │
│   └──────────────────────────────────────────────┘     │
└────────────────────────────────────────────────────────┘
```

### 顶部提示条:讲"生不生效",不讲状态

状态已经由头部第三个按钮表达,所以这里**不再重复展示状态**,只回答一个问题:下面这些设置现在算不算数。

用 `primevue/message`(`severity="warn"` / `"info"`)+ 新增的 `MESSAGE_PT` 预设,图标传 `lucide-vue-next` 的组件到 `#icon` 插槽。**不用 emoji、不写内联样式。**

| 文章状态 | severity | 文案 |
|---|---|---|
| `hidden` | `warn` | 本文还是草稿,下面的设置暂不生效。发布后按此生效。 |
| `scheduled` | `info` | 将于 {时间} 自动发布,届时按下面的设置生效。 |
| `visible` | — | 不显示(设置正在生效,无话可说) |

保留它的理由:"状态 × 受众"是个乘法,**草稿状态下这整块设置其实一点效果都没有**,不说的话作者会以为自己已经限制住了。

### 「谁能看到这篇」四档

| 档位 | 写入的字段 | 说明 |
|---|---|---|
| 跟随分类「X」的设置 | `audience=''`(默认) | 展开显示分类算出的有效受众(后端已下发 `audience_eff`/`audience_from`) |
| 所有人 | `audience='public'` | |
| 登录后可见 | `audience='authenticated'` | 展开摘要复选框 |
| 仅我指定的人 | `audience='restricted'` | 展开摘要复选框;可见性来自下方名单的「可查看」 |

摘要复选框 ↔ `teaser`:勾选 = `1`,不勾 = `0`。**跟随分类档下不显示它**(那时 teaser 也该继承,值保持 `-1`)。

**比分类更宽松的档位一律禁用** —— 详见 §7.1,这是本次设计里最实质的一条。

## 5. 权限档位映射

| 档位 | 存库 `access` | 含义 |
|---|---|---|
| 可查看 | `V` | 只能在公开站看到这一篇(不进后台) |
| 可编辑 | `V,R,U` | 能在后台读和改 |
| 可管理 | `V,R,U,D,publish` | 能改、能发布、能删 |
| 自定义(只读档) | 原样 | 不匹配上面任何一档的存量数据 |

**为什么「可编辑」自动含 `V`**:否则把一篇受限文章分享给同事共同编辑,他在后台能改、在公开站打开却是 404 —— 他会当成 bug 报给你。而"能改这篇的人"本来就能把它改成公开,所以补 `V` 不扩大实际能力。

## 6. 名单里的三种特殊行

| 行 | 呈现 | 为什么需要 |
|---|---|---|
| **作者本人** | 固定首行,「作者 · 始终可编辑」,不可删 | 作者靠 `own` scope 生效,不在 `resource_grants` 里。不显示的话,"我没在名单里为什么能改"没人能理解 |
| **从分类继承的授权** | 只读行,标注来源分类名 | 与分类编辑器里刚做的继承展示同一个道理:级联下来的配置不可见,作者会在"名单为空"的同时其实已被授权 |
| **不匹配档位的存量行** | 显示成最接近的档位 + 「自定义」标记 + 悬浮提示原值 | 见 §3.2:只在用户动它时才写 |

## 7. 必须处理的边界情况

1. **比分类更宽松的档位直接禁用,而不是"允许选 + 事后警告"。**

   后端沿父链**取最严**([public-access.md §3](public-access.md)),所以分类是「仅指定的人可见」时,文章侧选「所有人」**不会有任何效果** —— 存进库了,但判定时被父链压回去。

   一个点了没有反应的选项,比一句警告更糟。所以:**只允许选择"不比分类更宽松"的档位,更宽松的置灰**,禁用原因写在 tooltip 里。

   | 分类的有效受众 | 文章侧可选 | 置灰 |
   |---|---|---|
   | 所有人 | 全部四档 | — |
   | 登录后可见 | 跟随分类 / 登录后可见 / 仅我指定的人 | 所有人 |
   | 仅指定的人 | 跟随分类 / 仅我指定的人 | 所有人、登录后可见 |

   置灰项的 tooltip:`分类「内部资料」限定为「仅指定的人可见」,这里无法放宽。`

   **收益**:原本需要一整套"实际生效结果"的警告文案没有必要了 —— 那个会误导人的组合**变得点不出来**。少一条边界情况,而不是多一句提示。

   **存量数据的处理**:如果某篇文章库里已经是 `audience='public'` 而分类现在受限,那个档位要**显示为已选中但置灰**(带同样的 tooltip),**不静默改写**成别的值 —— 与 §3.2 同一个原则。
2. **选「仅我指定的人」而名单为空** → 除 super_admin 与持分类授权者外没人能看。要提示。
3. **有效受众是「所有人」时,名单里的「可查看」行暂时无意义**(人人都能看)。加一行次要说明"当前对所有人可见,此项暂无作用",**不删数据**。注意判据是**有效**受众(含分类继承),不是文章自己选的档位。
4. **无权改授权的人**:后端 `AclController.canManage` 要求对该行有 `U`。所以按钮对无 `U` 权限者应**隐藏**(或整个面板只读)。
5. **立即生效的失败处理**:每次改动一个请求;失败要回滚 UI 状态 + toast,不能让界面显示成已生效。
6. **移动端头部**:三个按钮 + 返回 + 标题在 <1024px 仍可能挤。方案:窄屏「保存」「权限」只留图标,「发布」保留文字(它是主动作)。既有的属性抽屉(FAB)不动。
7. **`▼` 是项目里还没有的 UI 原语**:全仓库没用过 `SplitButton`/`Menu`/`Popover`,`ui/presets.ts` 里也没有任何浮层类预设。定为 `primevue/splitbutton` + 新增 `SPLITBUTTON_PT`(见 §7A.3)。不能手写裸 `<div>` 浮层:lint 的 R6 会拦。
8. **从定时态改时间**:§4.2 的弹框里如果只给"取消定时",改时间就等于"取消 → 重新定时"两步。若加「立即发布」按钮,建议顺带给「改时间」。

## 7A. 组件与样式的硬性要求

1. **不用 emoji**。图标一律 `lucide-vue-next`(项目既有依赖):提示条 `LucideInfo`/`LucideTriangleAlert`,权限按钮 `LucideLock`,定时 `LucideClock`,下拉箭头 `LucideChevronDown`。
2. **不硬编码样式**。外观全部取 `ui/presets.ts` 的令牌/预设;本次要**新增两个预设**(它们目前一个都没有):

   | 新增 | 用于 | 为什么必须进 presets |
   |---|---|---|
   | `MESSAGE_PT` | `primevue/message` 的提示条 | 全仓库还没有任何提示类组件的预设,直接写 class 会被 lint 的 R6/R11 抓 |
   | `SPLITBUTTON_PT` | `primevue/splitbutton` 的「发布 ▼」 | 同上;浮层类预设以后一定还会用到 |

3. **`▼` 用 `primevue/splitbutton`**,为它做新预设。它内部是 `Button` + `TieredMenu`,pt 结构(已查实)如下:

   | pt 槽 | 是什么 | 预设怎么给 |
   |---|---|---|
   | `root` | 外层容器 | `inline-flex`,让两半贴合 |
   | `pcButton` | 主体「发布」按钮 | **嵌套的 Button pt 对象**`{ root: … }`,复用 `BTN_SHAPE` 尺寸 + `BTN_TONE.primary` 配色,但**只留左侧圆角** |
   | `pcDropdown` | `▼` 按钮 | 同上,**只留右侧圆角**,窄一档(`px-2`),与主体之间一道分隔线 |
   | `pcMenu` | 浮层(TieredMenu) | 其 pt 槽:`root`/`rootList`/`item`/`itemContent`/`itemLink`/`itemIcon`/`itemLabel`/`separator`。外观**照 `SELECT_PT.overlay` 的既有写法**(同样的白底/边框/圆角/阴影/`z-9999`),让全站下拉浮层长一个样 |

   注意 `pcButton`/`pcDropdown` 的值是**嵌套对象**而不是 class 字符串。视觉上要重调两半的圆角与分隔线 —— 这是用 SplitButton 必付的代价,已知并接受。
4. 定时选时间的对话框复用既有 `AdminModal` + `DATEPICKER_PT`;各类确认框复用既有 `useConfirm()`(项目里已广泛使用)。

## 11. 实现记录(与计划的偏差)

### 偏差 1:多加了一个 `RADIO_PT` 预设

四个档位是单选,而 lint 的 R6 不许裸 `<input type="radio">`。项目里既没有 radio 的预设,也没人用过 `primevue/radiobutton`。所以除计划里的两个预设外,还加了 `RADIO_PT`(结构与既有 `CHECKBOX_PT` 同形:`root`/`input`/`box`/`icon`,圆形 + 实心点)。

### 偏差 2:`AdminModal` 加了两个通用 prop

定时对话框有三个动作(立即发布 / 更新时间 / 取消定时),而 `AdminModal` 的 footer 只给一个主按钮。加了:

- `hideSave` —— 隐藏 footer 主按钮,动作放正文里
- `cancelText` —— 覆盖取消按钮文字(定时框里改成「关闭」,否则和「取消定时」撞车)

两个都是通用的,没有为这一个场景特化。

### 偏差 3:面板**不接 `article` 对象**,只接需要的字段

原本想传 `:article="{ ...form, status, ... }"`。实测这是个真 bug:行内字面量每次渲染都是新对象引用,**正文每敲一个字**都会让面板的 watcher 重跑,把用户刚选中的档位打回未保存的旧值。

改成传 `audience` / `teaser` / `status` / `publishAt` / `authorId` 五个具体字段,watcher 只盯 `[audience, teaser]`。

### 下拉菜单项没有图标

SplitButton 的 `▼` 里那项「定时发布…」只有文字。PrimeVue 的 menu `icon` 走 PrimeIcons 的 class,本项目没装那套字体图标;而自定义 item 模板要依赖 TieredMenu 的 slot 内部约定 —— 不值得为一个图标去赌一个库内部结构。

### 偏差 4:teaser 的覆盖关系也要禁用,不只是提示

原设计只把「比分类更宽松的**受众档位**」置灰,漏了 `teaser`。它其实是同一个问题:后端在**所有施加了限制的层级**之间对 teaser 取**最小值**(0 更严),所以文章只能把摘要墙关得更严,**放宽无效**。

实测后端五种组合(`accessEffFromChain`),与 UI 规则对照:

| 分类 | 文章 | 后端结果 | UI |
|---|---|---|---|
| `restricted` teaser=0 | `restricted` teaser=1 | `restricted`(文章的 1 被压回) | 复选框**禁用** + 说明 |
| `restricted` teaser=1 | `restricted` teaser=0 | `restricted`(文章收紧,生效) | 可勾,提示"取消勾选=完全隐藏" |
| `restricted` teaser=1 | `restricted` teaser=-1 | `restricted`(**-1 在受限层等于 0**) | 显示为未勾 —— 准确 |
| `public` | `restricted` teaser=1 | `restricted_teaser` | 可勾,自由 |
| `restricted` teaser=1 | 跟随分类 | `restricted_teaser` | 复选框隐藏(此时文章的 teaser 完全不参与) |

第三行是最容易误判的一处:**文章一旦自选受限档,它的 `teaser=-1` 就不再是"继承分类",而是当 0 用**。UI 把它显示成未勾选,与实际效果一致。

### 偏差 5:分类状态**永远**标出来,不只在受限时

原设计只在分类受限时显示那行说明。但「跟随分类的设置」下面空着的时候,作者分不清是"分类本来就是公开的"还是"这行没加载出来" —— 那就是让他猜。改成任何时候都标(`分类当前:所有人可见` / `分类当前:仅我指定的人 · 完全隐藏(继承自「X」)`)。

### 两个上线即现的 bug(实现后由使用发现)

1. **定时对话框与权限面板有一片英文。** 中文 `action` 组的替换没匹配上,`publishNow`/`updateSchedule`/`cancelSchedule`/`close` 只进了 en。已补,并加了一个校验:把这几个文件里所有 `$t()` 的键提取出来,逐个确认 en 与 zh 都有。
2. **定时选择器显示 `NaN NaN NaN.NaN NaN:NaN`。** DYAPI 把空的 Date 列返回成**字符串 `"null"`**(和 `data` 字段返回 `'null'` 是同一个毛病),`new Date("null")` 是 Invalid Date。已在 `Editor.loadArticle` 的边界处用 `toDate()` 归一,发布按钮组件里也加了一道防御。

### 验证

- `npm run lint`(设计系统规则)/ `vue-tsc` / `vite build` 全过。
- teaser 覆盖关系逐组合对过后端(见偏差 4 的表)。
- i18n 键存在性:提取这次涉及文件里的全部 `$t()` 键,en/zh 双语校验通过。
- 面板依赖的数据链路实测齐全:`manageable-categories` 返回的分类行带 `audience_eff`/`audience_from`/`parent_id`;文章详情带 `author_id`/`publish_at`/`audience`/`teaser`/`status`;`/acl/articles/:id` 正常。
- **未做浏览器视觉确认** —— SplitButton 两半的圆角贴合、Message 的配色、四档置灰的观感都需要你眼过一遍。这次的 PrimeVue `isNotEmpty('')` 坑就是构建期发现不了的那类问题。

## 12. 后续清理(同一批改动)

### i18n:受众域文案统一到 `access.*`

原先同一个概念有**两套平行词汇** —— `form.audience*`(分类编辑器)与 `access.tier*`(文章面板),是分两次实现时各写一遍的结果,违反 CLAUDE.md 的「同一类东西单一出处」。更糟的是**同一个面板里混用两套**:单选项标签走 `access.tier*`(「所有人」),下面那行「分类当前:…」走 `AUDIENCE_LABEL_KEY` → `form.audience*`(「公开(所有人)」)。

现在受众域只有 `access.*` 一套(`access` 是**领域**名,不是界面名,所以分类编辑器也用它):

| 概念 | 统一后 |
|---|---|
| public | 所有人 |
| authenticated | 登录后可见 |
| restricted | **仅指定的人或角色**(原文章面板写「仅我指定的人」,在分类编辑器上不准 —— 那里的名单常是角色) |
| inherit | 跟随分类的设置 |
| teaser on/off | 显示摘要 / 完全隐藏(原先还有个「完全隐身」,三个词说一件事) |

`form.audience*` / `form.teaser*` 共 15 个键已删除。`acl.categoryAudienceHint` 里内嵌的旧措辞也一并改掉 —— 那是同一种漂移的另一种形态(文案**正文里**写死了另一处的措辞)。

### 删掉一行没必要的小字

`access.teaserOffHint`(「不勾:未登录访客完全看不到这篇…」)连 i18n 与渲染逻辑一起删。复选框本身已经说清了,再加一行解释是噪音。

### 一个假阳性:`remove`/`delete`、`unpublish`/`hidden` **不该合**

按 zh 值扫出的"同义重复"里,这两组是**假阳性**:en 侧分别是 `Remove`/`Delete` 与 `Hide`/`Hidden`,是真有区别的两个词,只是中文都塌成了一个。合并会丢掉英文的区分。

正确修法是**把中文区分开**:`action.remove` 改成「移除」(它用在 FileUploader 的"从列表里移除这一项",本来就不是删除记录)。`action.unpublish`(动词「隐藏」)与 `contentStatus.hidden`(状态名「隐藏」)保持两个键 —— 词性不同,中文恰好同形。

**教训**:按值找重复只能作为线索,判断要看 en/zh 两侧 —— 中文缺少词形变化,会把动词和名词、近义词都塌成同一个字符串。

### 修掉一个既有 bug:安装向导的按钮显示原始键名

`SetupWizard.vue:177` 引用 `auth.completeSetup`,而这个键在 en/zh **都不存在**(来自更早的提交 `770c564`),所以新站点的安装向导上那个主按钮一直显示的是键名本身。

修法不是往 `auth` 组补一个键:它的兄弟 `setup.importAndInit` 就在同一个三元表达式里,这条文案属于**安装向导**这个域。所以加进 `setup` 组并改代码指向 —— 同 `access.*` 那次一样的「领域单一归属」。

顺带把 i18n 的校验做严了:上一版扫描只认单引号与反引号的 `$t('…')`,**漏了双引号写法**。现在覆盖三种引号 × `$t`/`t` 两种调用 × 全部 109 个文件(含 `frontend_themes/`),并把**拼接式**键(`$t('contentStatus.' + status)`)单列出来人工确认 —— 脚本查不了的那部分要说出来,不能假装查过了。结果:270 个静态键在 en/zh 全部存在。

### neo 主题:关于页的配图改用文章缩略图

`AboutPage` 原先从 `theme_neo_avatar` 这个**主题配置键**取图,而它已经把那篇「关于」文章取到手了。于是同一个页面的标题/正文来自文章、图片来自站点配置,作者要改两个地方;而文章编辑器里本来就有缩略图字段和上传器。

改成 `article.thumbnail`,`configSchema` 里删掉该键。顺带也少一份换主题后会变成孤儿的站点级配置(同 `home_template` 那一类问题)。
